Key concept Anti-pattern

Documentation Theatre

The anti-pattern: documentation produced to satisfy a process rather than a reader — complete, compliant, and trusted by nobody.

Documentation written to be produced, not to be read. A wiki that satisfies an audit. A template filled in because the gate requires it. A landscape deck built for a steering committee and never opened again. It is complete, it is compliant, and everyone quietly knows to ask a person instead.

The tell is the question *"is it documented?"* — which is about the existence of an artifact, not about whether anyone can act on it. Theatre passes that question every time.

The death spiral

It is self-reinforcing, which is why it survives in organisations that are otherwise rigorous:

1. Documentation is written as a separate task, after the work, by someone under time pressure. 2. It is accurate on the day it is written and drifts immediately, because nothing connects it to the thing it describes. 3. Someone is burned by out-of-date documentation and learns to verify with a human. 4. Now nobody reads it — so nobody notices it is wrong — so maintaining it feels pointless. 5. It is maintained anyway, because the process demands it. Cost without benefit, permanently.

Why more effort makes it worse

The instinct is a bigger push: templates, a documentation sprint, a review gate. This raises the cost of producing theatre without touching the cause, which is separation — the documentation is a different artifact, made at a different time, by a different motive than the work.

Compare Living Diagrams: a diagram *generated from* the structure cannot drift, because there is no second copy to drift. That is the general principle. Documentation that is a by-product of the work survives; documentation that is a project about the work does not.

The honest test

Not "does it exist" but: when someone needs to know this, what do they actually do? If the answer is "ask Marieke" while a wiki page sits there describing exactly that, you have measured your documentation's real value. The gap between the artifact and the behaviour is the size of the theatre.

What replaces it

- Structure that *is* the documentation — the model, the schema, the folder-note, the decision record written when the decision was made. - Generated views over that structure, never hand-transcribed copies. - Maps at every layer, so orientation is assembled from current artifacts (Maps Everywhere). - Ruthlessness about deletion: documentation nobody reads should be removed, not updated. Its presence is worse than its absence, because it signals a coverage that does not exist.

Maps Everywhere

Every layer of the system carries a map of itself — vault, repo, database, app, decisions. No blind spots, because orientation is a built artifact, not a memory.

Every layer of the system carries a map of itself. Not one index at the top, not a wiki someone maintains on Fridays — a map at each level, generated or curated where that level lives, and readable by both a person and a machine.

A Map of Content is the building block: one hub for one theme. Maps Everywhere is the principle: apply it *at every layer*, until there is nowhere in the system you can stand and not know where you are.

Why it beats "clarity"

Clarity is a virtue word. Everyone claims it, nobody can be held to it, and it tells you nothing about what to *do* on Monday morning. You cannot open a repo and check whether it is clarity-compliant.

Maps Everywhere is falsifiable. Point at any layer and ask: where is its map? If a folder has no folder-note, a database has no schema mirror, a repo has no purpose statement, an app has no model view — you have found a blind spot, and you know exactly what to build. It turns an aspiration into a checklist.

That is the difference between a value and a practice. Clarity describes how the result should *feel*. Maps Everywhere describes what you *build* to get there.

What it looks like in practice

| Layer | Its map | |---|---| | Knowledge / vault | MOCs per theme, marked `type: MOC` — queryable, not just readable | | Folders | Folder-notes: what lives here, why, what it is for | | Repos & apps | Purpose, code location, published artifacts, status | | Databases | A schema mirror — the system as a row in its own model | | Decisions | Decision records *with* the alternatives that lost | | The system itself | A Backroom: data model, sources, relationships, releases, artifacts |

The pattern repeats deliberately. Same instinct, different altitude.

Why it matters more as AI generates more

Generation scales; comprehension does not. When a system produces models, diagrams, code and records faster than a human can read them, the constraint stops being production and becomes orientation. Maps are what keep a fast-growing system understandable — for the person who has to change it in six months, and for the agent that has to reason over it today.

This is the guard rail, stated positively. Not "review everything" — nobody does — but *make sure every layer can tell you what it is.* An LLM turned loose on eighty thousand files retrieves plausible fragments. An LLM that finds a map first knows the shape of the thing before it starts searching. Structure beats magic, applied recursively.

The failure mode it names

The opposite of Maps Everywhere is not chaos — it is local tidiness with global blindness. Every folder looks reasonable up close; nobody can say what the system *is*. Work gets redone because it could not be found. Decisions get relitigated because the reasoning was never recorded. The map exists only in one person's head, which means it does not exist.
